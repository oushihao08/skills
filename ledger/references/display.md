# 展示骨架：固定含义，灵活布局

首页顺序：目标/范围/更新时间 → 总数与互斥状态 → 需关注事项 → 下一步 → item表 → 证据与历史链接。

- **清单**：item、当前状态、阶段进度、业务结论；可增加本任务有用的负责人、产物等列。
- **矩阵**：一item一行、每阶段一列；不同item未包含的阶段显示“不适用”，不是未开始。阶段标题取任务定义。
- **分组**：按业务组分别展示，不为凑统一表头压平不同流程。
- **auto**：阶段集合相同且多阶段时用矩阵，否则用清单；不会自动把示例数量/阶段变成规则。

主表写简要结果；复杂尝试、完整错误和多条证据放可折叠明细。正常成功不铺满首页，问题区突出失败、受阻、未知、过期及未解决观察。自定义列从details取值，不重新计算或凭空推断分数、账号、交付状态。

折叠历史列出全部观察的类型、状态、摘要、影响及原记录链接，包括已解决问题、成果和经验；首页仅突出open观察。

展示区分“阶段执行成功”“item验收通过”“上传回执”“远端回读”等事实。阶段统计每个状态互斥，另按阶段列成功数/适用数。标注 skipped、非必需阶段和未核实时间；不生成模糊的‘大致80%完成’。

支持Agent按当前任务调整presentation及业务字段；如需要额外人类说明，另写解释并引用对账台，不手工维护另一张带独立状态的表。模板不是固定任务清单，不替用户增加验收要求。
