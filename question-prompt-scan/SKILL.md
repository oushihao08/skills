# 题面格式与生产残留扫描

使用配套脚本完成完整取数和字符定位，Agent只判断候选的实际用途。检查对象是当前出题结果的`question`，不是整个题包。扫描不鉴定AI来源、不产生达标门槛。

## 范围与入口

- 从当前请求确定项目/期次、达标状态和数量；“所有”不抽样。未指定状态时使用`accepted`并说明。示例中的项目名不是固定范围。
- 先读目标仓库AGENTS.md；核实当前API及脚本适配的契约。默认本机HTTP API，不直连数据库、不读取密钥、不调用生成模型。脚本只发GET。
- 当前脚本适配ai-distill的`GET /api/projects`、`GET /api/projects/:id`及`GET /api/workflows/:id`；这些列表当前不分页。接口变化时先适配完整分页，不能仅扫描第一页。名称精确匹配，重名用ID消歧，不能模糊选择。
- API详情可能返回其他字段；脚本立即丢弃，仅输出题面、定位身份、版本/哈希和候选。不要让Agent读取或保存完整API响应，不读附件、rubric、作答思路、标答、模型回答和评分正文；达标状态仅用于筛选。

```sh
python3 /Users/jack/.agents/skills/question-prompt-scan/scripts/scan.py --project '用户指定的完整项目期次名' --status accepted --out '/非输入目录/本次扫描'
```

API地址可用`--base-url`指定本机端口；状态可选`accepted`、`repair`、`all`。仅在用户要求时扩大范围。`--project-id`可替代名称。输出目录必须不存在，放在任务产物区，不放材料、业务Skill或冻结附件目录。

脚本生成`prompts.json`（只含题面及定位）、`scan.json`（覆盖及候选）、`候选清单.md`。逐题原子保存`progress.json`，结束核对失败仍导出已读题面及错误；前置失败写`failure.json`。错误记录阶段、题目ID、原因码和可用HTTP状态，不保存响应正文。退出2表示不完整，不能把失败题算无问题；可用同一范围重新只读查询，不自动扩充或改题。

离线扫描使用同一窄投影：`--input prompts.json --out 新目录`，文件为`{"items":[{"workflow_id":"…","title":"…","question_version":"…","question":"…"}]}`。不把整题包作为输入。没有上次完整覆盖标记`complete:true`时，只声明所给条目扫描完成，整批覆盖未确认（退出2）；不能把部分进度包装为全量结果。

## 判断候选

脚本检出JSON/XML/HTML包装、Markdown语法、`[]/【】/<>/{}`、模板变量、模型/角色标记、工具/引用/转义残留及生产说明。正则命中只是线索，既不自动删除，也不按命中数量判AI感。

逐项读取所在句及必要的前后题面，判为：

|结论|依据|
|明确残留|与业务无关的提示词角色/生产指令、未填的生成占位、运行信息或失效引用等外露|
|正常保留|有业务用途的标题列表、引文、案号/签署待填、脱敏符号、模拟披露、计算区间、必要代码或数据|
|需确认|单靠题面不能确定用途或改后含义是否相同；不借读取标答补判断|

括号和整齐格式本身不是错误。例如`[请补充任务背景]`可能是生产占位；`[案号待核]`是业务占位；`[起日,止日)`是区间，后两者不能机械删除。语义完整的标题、编号、专业限定语也不为了“去AI”改掉。

在同一输出目录写`审阅结果.md`：项目及筛选范围、发现/读取/失败/有候选/确认问题题数；每条问题给题目ID、名称、版本、行列/原文片段、类型、结论和理由。按题统计覆盖，区分候选数与确认问题数。未逐项审阅时只报告机器候选；无命中只表示本次模式未检出，不代表没有任何残留。

## 修改边界

“扫描、检查、取出”只授权读取及导出。用户明确要求修改时，制作最小精确替换补丁并运行下列工具，生成本地修改稿和差异；只清理外层包装或明显内部残留，不改事实、期限、权限、任务、交付要求或补造业务内容。无法保证等义的保留并标需确认。现有明确授权直接沿用。

补丁JSON：`{"items":[{"workflow_id":"…","question_version":"原版本","prompt_sha256":"原题面哈希","edits":[{"start":0,"end":6,"before":"精确原文","after":"替换文字或空串","reason":"确认理由","confirmed":true}]}]}`。字符位置为原题面的Python字符偏移，左闭右开；同一题的修改不得重叠。`confirmed`由Agent审阅后填写，不由正则自动填。工具核对ID、原版本、全文哈希、区间及原文，任一不符整批不应用；这些检查不证明语义等价。

```sh
python3 /Users/jack/.agents/skills/question-prompt-scan/scripts/patch.py --input '/扫描目录/prompts.json' --patch '/扫描目录/patch.json' --out '/新目录/修改稿'
```

生成`changes.json`和`changes.diff`，保留原快照不动。修改稿明确标记尚未入库，不能称为当前有效题面。先核对差异和必要业务信息，不能仅凭工具成功宣称完成业务修改。

两个脚本都没有API写回能力：当前项目未提供通用题面编辑API，不直写数据库、不冒用恢复历史结果接口。用户要求入库时先明确这一实现缺口并按授权范围处理，不能把本地修改稿说成已经写回；后续具备正式接口时仍须校验最新版本、写后回读并按原流程处理作答、评分与达标绑定。不能保留旧达标资格冒充新版本验证。本Skill不授权重启、模型调用、重出、评分或发布。
