# 识别叙事本质

## 本质的定义

这里的“本质”不是案例的主题概括，也不是把具体名词换成更抽象的词。它是解释案例选择的**决策关系**：面对什么观众理解障碍或内容约束，作者用某种表达选择完成了什么叙事任务；换掉案例中的人物、事件、素材或顺序后，什么判断仍能指导新选择。

一条原则只有同时满足以下条件，才算提炼到可迁移层：

1. **解释力**：说明表达选择解决了什么问题，不只给手法贴标签。
2. **去实例化**：替换案例主题、素材和顺序后，原则仍然成立。
3. **决策价值**：能指导新案例在不同实现方式之间作选择，不是“要吸引人”“要有冲突”一类空话。
4. **条件与边界**：说明何时适用、何时不适用；不把推测的观众效果写成已证实因果。

分析时保留具体证据；提炼时保留决策关系，去掉案例专属实现。不要把本期手法顺序改名后当作通用原则。

## 适用范围

当任务需要解释某个具体内容案例为什么这样组织，并把分析迁移到新题材时使用。触发点是“案例实现与可复用原理容易混淆”，不是媒介形式本身，也不是用户是否用了“本质”“底层逻辑”等关键词。

不把本 Skill 当作所有领域的通用根因分析框架。仅在任务涉及内容叙事、传播表达或案例经验迁移时使用。

## 工作流程

### 1. 找到真正待解决的叙事问题

先从用户目标和案例材料确认：

- **表面现象**：案例用了什么开场、事件、人物、顺序、语气或转折。
- **传播目标**：这段内容希望观众理解、期待、感受或采取什么行动。目标未明示时标为推断。
- **叙事障碍**：观众理解目标内容时会遇到什么阻碍，或创作者必须处理什么材料约束。
- **本质问题**：案例必须解决的核心叙事障碍。它应能解释多个表达选择，不能只复述题材、标题或某个爆点。

依据现有材料判断；若目标、障碍或动机存在多个合理解释，标为推断或保留候选，不要冒充确定事实。

### 2. 还原案例的具体决策

按用户需要记录时间段、原文或情节。对每个关键选择回答：作者在这里选择了什么；当时需要解决的叙事障碍是什么；该选择怎样服务目标。先从证据归纳，不预设案例符合熟悉的套路。

### 3. 提炼可迁移的决策关系

将案例选择表达为条件关系，而不是固定流程：

> 当【观众障碍 / 材料约束 / 传播目标】成立时，需要完成【叙事功能】；具体可用【由新材料支持的不同实现】，不固定为案例手法。

填入关系时，不要求每项都齐全。没有依据的目标、观众心理或因果关系应标为未知，不要为凑完整框架而编造。

### 4. 做双向抽象检查

**检查是否仍然太具体：**替换案例中的人名、事件、行业、平台、奇观和金句。若原则仍规定同一段落顺序、情绪曲线或素材类型，它只是案例模板，继续抽象。

**检查是否抽象过头：**若原则只剩“吸引人”“制造冲突”“层层递进”，补上它针对的障碍、决策条件和适用边界。

**检查决策价值：**为同一叙事功能想出至少两种不同实现。若原则只能容纳本案例的原手法，它仍然太窄；若各种做法都能套用却无法帮助取舍，它仍然太空。

### 5. 分开证据、推断与原则

分别记录：

- **案例证据**：具体内容、时间点和顺序，只证明该案例如何实现。
- **分析推断**：作者意图、观众心理或效果判断，注明证据强弱。
- **可迁移原则**：决策关系、适用条件和其他可选实现，不含本案例专属素材。

用户要求形成文档时，直接在指定文档中完成。保留可追溯的案例分析，不把案例细节塞入通用模板；不为追求抽象而删除证据。

## 输出结构

按任务需要精简或展开，优先使用下表连接证据与抽象：

| 案例证据 | 叙事障碍与局部决策 | 可能的观众机制 | 可迁移的决策关系 | 替代实现与边界 |
|---|---|---|---|---|
| 时间点/原文/情节 | 案例在解决什么问题、选择了什么 | 文本可见效果与推断分开 | 什么条件下需要完成什么叙事功能 | 哪些不同做法可实现；什么不能推断 |

在表格外说明：本案例的核心叙事障碍；可迁移的决策关系；仍属推断或缺少传播数据的部分。

## 示例：同一观察，避免把实现方式固化

以下仅示范抽象过程，不是推荐开场公式。

| 层次 | 示例判断 |
|---|---|
| 案例观察 | 某期视频先用比较建立尺度，再呈现更反常的说法，随后提到事件影响。这里的具体比较对象和说法只属于该视频。 |
| 叙事障碍与局部决策 | 本期需要让陌生现象变得可理解，并让开场注意力转向正文要解释的对象；案例选择了比较、反差和影响信息。 |
| 可能的观众机制 | 反差可能制造意外感，影响信息可能让观众判断重要性；实际留存与心理反应需要观众数据，不能只凭文稿断言。 |
| 可迁移的决策关系 | 当观众尚不知道某个主题为何值得关注时，开场需要提供有材料依据的观看理由，并与正文的解释目标相连。 |
| 替代实现与边界 | 可按材料选择用户困境、关键结果、利益冲突、人物处境、发现或其他入口；不要求比较、猎奇、逐级升级或追加影响。没有证据支持的影响不能用来抬高重要性。 |

## 常见错误

| 错误 | 修正 |
|---|---|
| 把案例元素改成上位词，就声称完成抽象 | 继续写出它解决的叙事问题、观众机制和适用条件；上位词本身不是本质。 |
| 把案例的具体先后顺序写进“通用结构” | 将顺序标为本期观察；通用部分说明功能和可选实现。 |
| 把“可能吸引观众”说成已验证的效果 | 区分写作意图、文本可见机制和真实传播数据。 |
| 为了让案例符合熟悉结构而补充动机或因果 | 只使用来源支持的内容；其余标为不确定或不推断。 |
| 抽象到“要有冲突/反转/悬念” | 检查它是否为当前材料所需；说明没有该元素时如何组织内容。 |
| 把一个案例的成功归因于单一手法 | 标出其他可能因素；没有对照或表现数据时，不作因果结论。 |

## 完成检查

- 每条可迁移判断都说明它解决的叙事障碍，并能追溯到案例证据或明确标为推断。
- 案例细节只出现在个案记录或示例中，没有伪装成普遍要求。
- 原则包含决策条件和叙事功能，不只给手法名称或泛化形容词。
- 原则可容纳至少两种不同实现，且能帮助选择；否则继续检查是否太窄或太空。
- 新题材可以得到不同的事件、开场和段落顺序，同时仍遵循同一底层判断。
- 没有把文本分析推成真实点击、留存、转化效果；没有把有趣叙述推成事实证明。
