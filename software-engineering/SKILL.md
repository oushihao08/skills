# 软件工程

遵守全局 AGENTS.md 的目标、范围和授权规则。先明确本次要实现的行为、影响范围及成功证据，再调查原因或选择方案。

## 项目文档先读：理解约定后再判断和行动

- 分析问题、提出方案或修改代码前，先读取项目根目录及目标路径上适用的 AGENTS.md，并检查相关 CLAUDE.md；跨模块时补读目标模块的规则，不把局部约定套到整个项目。
- 按任务读取 AGENTS 、README、docs/ 中相关的需求、架构、设计、接口及开发说明；继续读取其中与当前任务直接相关的引用文档。只读目录名或摘要不算理解所需约束。
- 将文档中的目标、约束、接口契约和验收要求纳入方案与验证。文档描述的预期与源码的实际行为不一致时，先核实版本和适用范围，不擅自认定任一方正确。
- 阅读范围以足够支撑当前判断为准，不无差别通读。文档缺失时从代码和现有证据继续调查；仅在满足询问条件时打断用户。

## 执行约束：保持已有功能，优先复用

- 尽量保持既有功能、接口和业务行为；必要的根因修复可以调整相关实现，不能为少改而保留缺陷。
- 新增前查找并优先复用已有组件、函数、状态和业务流程，避免重复规则；代码相似但语义不同，不强行合并或堆叠分支。
- 新代码职责清晰，保留合理复用性；存在明确复用需求再抽取公共能力，不为假想需求搭框架。
- 不擅自重构、不顺手清理无关代码、不加计划外功能。保留用户已有修改，不擅自覆盖或回退。

## 运行与验证

- 对照实际调用方、数据流和接口契约检查改动。分别报告源码检查、运行验证和业务验收的结果。
- 未经用户明确要求：不运行测试、lint、dev server；不执行 npm install / pnpm add；不改 package.json；不创建测试文件。不得换用等价命令绕过禁令。

## Jack 工程偏好

- 主栈 Vue 3 + UnoCSS + Capacitor + TypeScript；沿用项目已确认的技术与约定，不为套用偏好迁移技术栈。
- Vue 使用 script setup；布局优先 Row/Column，不用 div + flex；样式优先 UnoCSS 原子类。
- 使用已配置的自动导入，不乱写 import；async 必须有 try/catch，不留空 catch。
- 不使用过时方案；涉及易变的技术事实时核对当前项目版本和官方资料。
- 迁移 OpenCode 配置时只迁移可映射概念，不原样照抄配置结构。
