# Pace：提效

缩短达到合格交付的总时间，减少无效工作和返工。持续寻找更短的有效路径；只在新信息值得改变安排时重排。不以忙碌、并发占满、工具调用少或单步快代替目标完成。

## 选择当前路径

- 从本次目标、交付标准和授权出发，核对已有成果、当前状态、可用工具及硬约束。简单任务直接做，不额外建表、计时或制定计划。
- 对需要编排的任务，只保留足以决定下一动作的信息：剩余工作、前置依赖、实际阻塞、共享资源和恢复入口；沿用已有计划，不另建调度台账。
- 比较可行路径的剩余执行、等待、切换、验证及返工成本；未知时间注明估计，不为选择路径做比执行更贵的调查。不承诺未经证明的全局最优。
- 先去掉重复调查、重复生成、无效重试和多余往返，再调整顺序和并发。优先复用同输入版本的有效产物、现成工具、已知入口与可复现路径；版本或适用条件变化时重新核验。

## 编排与等待

- 优先解除决定整体完成时间的阻塞；用户有交付优先级或截止时间时一并考虑。按项滚动衔接就绪下游，不因整批未结束而闲置独立工作；明确要求阶段整批执行时遵守原要求。
- 只有输入、输出及副作用互不冲突的工作才并行。只读检索在不争抢关键资源时批量；共享文件、表单、账号任务或业务记录采用单一写入者或已验证隔离。委派仅在已获授权且收益超过沟通和重复上下文成本时使用。
- 等待时选择同一目标内已授权、可中断、不会改变在途输入且不争抢关键资源的准备工作；收益不足以覆盖切换和接续延迟时不插入。主任务恢复就绪后及时返回，次要事项不能无限占用资源或长期饿死必需工作。
- 优先等待事件、任务句柄或有界长轮询；否则按预期完成窗口和变化情况调整检查间隔。保留下一检查条件和时间，不忙轮询、不用固定长睡眠代替状态判断，不声称退出当前执行后仍会自动监听。

## 并发按瓶颈调整

区分排队未领取、依赖未满足、本地资源不足、供应商限流、外部执行和状态未知。先查目标任务明细、时间戳及当前生效配置，不从汇总计数或旧记录推定原因。

- 只有可运行积压且存在资源余量时，才在授权和实际上限内逐步增加并发；比较相近任务的完成量、延迟、失败/限流及资源压力。退化时撤回本次调整，不取消既有任务来制造空槽。
- Agent、API、CPU、内存、网络和浏览器不是可直接互换的额度。替换执行器必须同时满足授权、输入/工具能力、隔离及交付契约；同等质量不足以单独授权替换。
- 当前上限、执行器归属或重启要求阻止调整时，明确限制；不启动另一套进程绕过限制。没有可运行工作就接受空闲，不制造任务。

## 何时重排

| 观察 | 判断与动作 |
| --- | --- |
| 正常推进，没有新信息 | 继续已有路径；不重复规划或复核未变化事实。 |
| 新工具、有效成果或更短入口出现 | 比较剩余成本；先核对原路径已产生的副作用与恢复点，再切换。沉没成本不是继续理由。 |
| 新依赖、输入变化、异常或明显超出预期的等待 | 核实原因，调整受影响的剩余工作；无关成功结果保留。 |
| 响应超时、回执不明 | 按原任务/请求ID查询，标未知。重试先确认原请求终态或已验证的幂等/防重契约；停止原任务另按已有授权。不把超时直接当失败或换ID盲重发。 |
| 检查与记录开销超过预期收益 | 减少检查频率与记录粒度，保留必要身份、状态和验收证据。 |

## 重复操作与交付

先验证一个完整操作路径，再复用明确入口、文件映射和批量能力。缓存校验绑定输入/产物摘要，内容未变才复用；写入或依赖外部状态作决定前核对相关的账号、任务身份、权限及提交状态，不在每一步重复全量查询。

网页上传时提前准备正确产物和任务映射；上传、正式提交、回执与外部验收分别确认。同一表单串行操作，等待期间可准备下一项，不在未确认提交时替换附件。是否需要编辑器或平台检查由当前任务契约决定，不能为了快跳过必需步骤；非阻断提示也不无限等待。

不省必要验证、不降质量、不擅换模型或改业务规则。更快但结果失效、串题、重复提交或需要返工，不算提效。

## 记录与协作

与goal-work并用时，由其保存目标和验收；Pace只优化当前执行安排。已有Trace或等效记录时，仅记影响恢复/复用的瓶颈证据、路径调整、结果与限制，不逐条记命令，不为每次轮询增加记录。

只在有重要调整时简报“瓶颈、改动、依据”。收尾区分已测耗时与估计；没有可比数据不报提速比例。完成本次目标即停止，不追加优化项目。具体领域操作遵守对应skill和工具契约；本skill不是常驻监控器或程序调度器。
